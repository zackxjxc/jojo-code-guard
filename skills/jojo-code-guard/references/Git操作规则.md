# Git 操作规则

只在用户请求暂存、提交、推送、改写历史、配置 Git、安装 Hook、检查历史提交或整理提交边界时加载。
通用文件守护内部只读执行 `git status`、`git diff` 或 `check_diff.py` 不触发本规则。

## 状态与授权

- 提交或改写 Git 状态前读取 `git status --short`、相关 diff 和仓库规则，保留用户已有修改。
- 不自动暂存无关文件，不把来源不明的修改混入提交，不使用破坏性恢复命令覆盖工作区。
- 安装 Hook、修改 Git 配置、执行批量 renormalize、rebase、reset、push 或历史改写前确认具体授权和影响范围。
- `core.autocrlf`、`core.eol`、`.gitattributes` 与项目文本规则冲突时先报告，不通过 checkout 或重新暂存试错。

## 提交边界

- 只有用户授权提交时才创建提交。
- 每个提交围绕可独立审阅和回退的最小功能单元，不混入无关修改，也不为两三行机械拆分无意义提交。
- 复杂任务应按可独立审阅的正常开发阶段拆分，使审阅者能沿提交历史理解实现过程；中间验证按风险和
  里程碑安排，最终交付前必须完成与风险相称的测试和 diff 检查。
- 提交信息使用中文，一句话准确说明变更目的；项目已有约定时优先遵循项目约定。

## 编码迁移与门禁

- 不自动执行 `git add --renormalize`，不批量改写历史文件或暂存区。
- 用户明确授权单文件编码、BOM 或换行迁移时，使用精确路径许可，不使用 glob。确定性参数和
  `JOJO_CODE_GUARD_ALLOW_MIGRATIONS` 的格式见 [使用与工具说明](usage.md)。
- Git pre-commit 只是提交阶段的机械门禁，不能替代编辑前后的最小 diff 守护。
