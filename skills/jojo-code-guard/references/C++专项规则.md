# C++ 专项规则

只在处理 C/C++ 源码、Visual Studio/MSVC 工程、资源脚本或相关旧工具链兼容问题时加载。其他语言项目不因
位于同一仓库而加载本规则。

## 适用目标

- C/C++ 源码和头文件，例如 `.c`、`.cc`、`.cpp`、`.cxx`、`.h`、`.hpp`、`.hxx`。
- Visual Studio/MSVC 工程文件，例如 `.sln`、`.vcxproj`、`.props`、`.targets`。
- Windows 资源文件 `.rc`、`.rc2`，以及明确涉及旧代码页、中文编译链或 CMake/编译器编码选项的任务。

## 编码与最小修改

- C++ 老项目可能同时存在 UTF-8、本地代码页和不同换行。已有文件逐个保真，不能按扩展名批量转成 UTF-8。
- 新源码仍优先遵循仓库配置；没有项目规则时才使用 UTF-8 无 BOM。
- Visual Studio/MSVC 的新增 `.rc/.rc2` 默认使用 UTF-8 BOM + LF，避免旧资源工具链误判中文；已有资源文件
  保持原状。
- 不因修改一行而整理 include、运行全仓 formatter、统一注释编码或重写工程文件。需要 clang-format 等
  格式化时，以项目现有配置和用户授权范围为准。
- 编译器参数、执行字符集、源码字符集或资源编译器行为与仓库文本规则冲突时，先通过实际构建和文件基线
  确认，不凭平台惯例批量迁移。

## 注释标记

- 普通代码说明使用 `//`；`///` 只用于项目已有约定或文档工具实际消费的文档注释，不用它替代普通注释。
- 注释内容和覆盖范围遵循项目规则，不为未修改的旧代码批量补注释。

所有写入仍必须执行 [通用文件守护](通用文件守护.md) 的编辑前后闭环。
